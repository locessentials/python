# CSES Geometría - Problema 4: *ray casting*

Hay un polígono con `n` vértices: (x1, y1), (x2, y2), …, (xn, yn). Cada vértice está unido al siguiente, y el último está unido al primero. El polígono es simple, es decir, sus lados no se cruzan. También hay una lista de `m` puntos. El objetivo es saber si cada punto está dentro del polígono, fuera del polígono o sobre su borde.

**Entrada:**
- Dos números `n` y `m`: el número de vértices y el número de puntos
- Después, `n` líneas con dos números enteros: las coordenadas x y y de un vértice
- Al final, `m` líneas con dos números enteros: las coordenadas x y y de un punto

**Salida:** Para cada punto, imprime "INSIDE" (dentro), "OUTSIDE" (fuera) o "BOUNDARY" (sobre el borde).

**Límites:**
- 3 ≤ n ≤ 1000
- 1 ≤ m ≤ 1000
- -10^9 ≤ x, y ≤ 10^9 (para los vértices y para los puntos)
- De tiempo: 1 segundo
- De memoria: 512 MB

Traducida de: [CSES Problem Set – Point in Polygon](https://cses.fi/problemset/task/2192)

## Concepto clave: *ray casting*

El ***ray casting*** (en español se describe como trazar un rayo) sirve para saber si un punto está dentro de un polígono. Desde el punto que se prueba, se traza un rayo horizontal hacia la derecha y se cuenta cuántos lados del polígono cruza. Si el número es impar, el punto está dentro, y si es par, está fuera. Cada vez que el rayo cruza un lado, pasa de dentro a fuera o de fuera a dentro, y al final siempre termina fuera, porque el polígono tiene un tamaño limitado y el rayo sigue sin fin.

Para cada lado, con extremos (x1, y1) y (x2, y2), y el punto (x3, y3), este bloque de la función `ray` decide si el rayo que empieza en el punto cruza el lado:

```
if (y1 > y3) != (y2 > y3):
    x_hit = x1 + (y3 - y1) * (x2 - x1) / (y2 - y1)
    if x_hit > x3:
```

### Primera condición: ¿el lado llega a la altura del rayo?

La primera condición revisa si el lado llega a la altura del rayo, es decir, si uno de sus extremos está arriba del punto y el otro no. Si el lado no llega a esa altura, el rayo no puede cruzarlo y no se cuenta.

```
if (y1 > y3) != (y2 > y3):
```

Cada parte entre paréntesis da True o False, y luego `!=` compara esas dos respuestas.

- `(y1 > y3)` pregunta: ¿el primer extremo está arriba del punto?
- `(y2 > y3)` pregunta: ¿el segundo extremo está arriba del punto?

Después, `!=` pregunta: ¿esas dos respuestas son distintas?

| ¿primer extremo arriba? | ¿segundo extremo arriba? | ¿son distintas? | significado |
|---|---|---|---|
| True | False | True | uno arriba y otro abajo: el rayo puede cruzar el lado |
| False | True | True | uno abajo y otro arriba: el rayo puede cruzar el lado |
| True | True | False | los dos arriba: el lado no se cuenta |
| False | False | False | los dos abajo: el lado no se cuenta |

Por ejemplo, con y3 = 5, y1 = 8 y y2 = 2:

```
(8 > 5) != (2 > 5)
True != False
True
```

Las dos respuestas son distintas, así que el lado va de arriba del punto a abajo de él, y el rayo puede cruzarlo. Esta condición va antes de la fórmula porque la fórmula trata el lado como una recta sin fin. Siempre encuentra un punto a la altura del rayo, aunque el lado real no llegue hasta ahí. 

Esta condición también evita un error en la fórmula de `x_hit`. En un lado horizontal, los dos extremos están a la misma altura (y1 = y2), así que `(y2 - y1)` vale 0, y Python se detiene con un error si se divide entre 0. Pero en ese caso `(y1 > y3)` y `(y2 > y3)` dan la misma respuesta, así que la condición da False y la línea de `x_hit`, que está dentro del `if`, no se ejecuta.

### Segunda parte: dónde cruza el lado

La primera condición indica que el lado tiene un extremo arriba del punto y el otro abajo, así que en algún lugar el lado está a la misma altura que el punto. Ese lugar puede estar a la izquierda o a la derecha del punto. Como el rayo solo avanza hacia la derecha, el lado solo se cruza si ese lugar está a la derecha, y eso es lo que revisan las dos líneas siguientes:

```
x_hit = x1 + (y3 - y1) * (x2 - x1) / (y2 - y1)
if x_hit > x3:
```

Con un ejemplo illustramos cómo funcionan estas does lineas. En este ejemplo, el punto que se prueba es (x3, y3) = (0, 3), y el lado va de (x1, y1) = (2, 1) a (x2, y2) = (10, 5). Los puntos siempre se escriben (x, y).

```
  y
  5 |                              *  (10, 5) = (x2, y2)
  4 |                        *
  3 |P-----------------o----------------->  rayo a la altura 3
  2 |            *
  1 |      *  (2, 1) = (x1, y1)
    +--------------------------------------> x
     0     2     4     6     8     10    12

  P = punto (x3, y3) = (0, 3)
  o = cruce (6, 3)
```

El rayo empieza en el punto (0, 3) y avanza hacia la derecha a la altura 3, así que el cruce también está a la altura 3. Lo único que falta encontrar es su `x`, y eso es lo que calcula `x_hit`:

1. Se empieza en un extremo conocido del lado, (x1, y1). Por eso la fórmula empieza con `x1 +`: parte de la x de ese extremo y le suma lo que avanza hacia la derecha. En el ejemplo: x1 = 2
2. `(y3 - y1)` es cuánto hay que subir por el lado, desde ese extremo hasta la altura del rayo. En el ejemplo: (y3 - y1) = (3 - 1)
3. `(x2 - x1) / (y2 - y1)` es cuánto avanza el lado hacia la derecha por cada unidad que sube. Como el lado es recto, ese avance es el mismo en todo el lado. En el ejemplo: (x2 - x1) / (y2 - y1) = (10 - 2) / (5 - 1)
4. Al multiplicar lo que hay que subir por lo que se avanza por cada unidad, se obtiene cuánto hay que avanzar hacia la derecha desde x1. En el ejemplo:

```
x_hit = x1 + (y3 - y1) * (x2 - x1) / (y2 - y1)
x_hit = 2 + (3 - 1) * (10 - 2) / (5 - 1)
x_hit = 2 + 2 * 8 / 4
x_hit = 2 + 4
x_hit = 6
```

Por último, `x_hit > x3` revisa que el cruce esté a la derecha del punto. El rayo solo va hacia la derecha, así que un cruce a la izquierda del punto no está sobre el rayo y no se cuenta. 

Entonces en nuestro ejemplo, `x_hit = 6` y el cruce es (6, 3). Como 6 > 0, el cruce está a la derecha del punto y sí se cuenta.

## Panorama del código

Para la entrada, el programa lee `n`, el número de vértices, y `m`, el número de puntos que hay que probar. Guarda cada vértice como una lista de dos números enteros, `x` y `y`, y pone todas estas listas en una lista principal, `vertices`, en el mismo orden en que aparecen en la entrada, que es el orden del contorno del polígono. Hace lo mismo con los puntos, que guarda en la lista principal `puntos`.

Después, un ciclo `for` revisa cada punto en dos pasos:

1. Con la función `cross`, que usa el **producto cruz**, revisa si el punto está sobre un lado del polígono. Si es así, imprime "BOUNDARY".
2. Si no, con la función `ray`, que hace el **ray casting**, revisa si el punto está dentro o fuera del polígono.

Como el producto cruz ya se explicó en los problemas 1 y 2, aquí solo se explica el segundo paso.

La función `ray` empieza con `result = False`, que equivale a cero cruces. Luego, para cada lado del polígono, hace las revisiones que se explican en la sección del concepto clave, y cada vez que el rayo cruza un lado, cambia `result`: con 1 cruce queda `True`, con 2 queda `False`, con 3 queda `True`, y así sucesivamente. Es decir, `result` no guarda cuántas veces el rayo cruza los lados del polígono, sino si ese número es impar (True) o par (False), y eso es todo lo que necesita el **ray casting**: impar significa dentro y par significa fuera. Al final, la función devuelve `result`, y el ciclo `for` imprime "INSIDE" si es True y "OUTSIDE" si es False.

## Análisis del código

- **Variables y tipos de datos:**
  - `int`: `n` (el número de vértices), `m` (el número de puntos), `vertice` (la posición del lado que toca revisar), las seis coordenadas `x1`, `y1`, `x2`, `y2`, `x3`, `y3` y `product`. Como las coordenadas son enteras, el producto cruz es exacto: `product == 0` no tiene errores de redondeo.
  - `float`: `x_hit`, porque la fórmula divide. A diferencia del producto cruz, este valor puede tener errores de redondeo muy pequeños.
  - `bool`: `result`, que indica si el número de cruces hasta el momento es impar (True) o par (False).

- **Estructuras de datos:**
  - Listas `vert` y `punto`: guardan los dos números de un vértice o de un punto, que las funciones separan en un solo paso, por ejemplo `x3, y3 = punto`.
  - Listas de listas `vertices` y `puntos`: guardan todos los vértices, en el orden del contorno del polígono, y todos los puntos que hay que probar.

- **Paradigma algorítmico:** ninguno en particular; es un cálculo directo. Para cada punto, se revisan todos los lados del polígono, primero con el producto cruz y luego con el *ray casting*.

- **Estilo de programación:** imperativo/procedural, con dos funciones: `cross`, que revisa si el punto está sobre algún lado, y `ray`, que hace el *ray casting* para saber si el punto está dentro o fuera.

- **Iterativo o recursivo:** iterativo. Dos ciclos `for` leen la entrada, otro recorre los puntos, y dentro de `cross` y `ray` un ciclo recorre los lados. No hay nada que dividir en problemas más pequeños, así que la recursión no ayuda.

- **Complejidad:**
  - Temporal: O(n * m), porque para cada uno de los `m` puntos, `cross` y `ray` recorren los `n` lados.
  - Espacial: O(n + m), porque `vertices` guarda todos los vértices y `puntos` guarda todos los puntos.
