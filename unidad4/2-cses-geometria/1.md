# CSES Geometría - Problema 1: producto cruz en 2D

Hay una recta que pasa por los puntos p1=(x1, y1) y p2=(x2, y2). También hay un punto p3=(x3, y3). El objetivo es determinar si, mirando desde p1 hacia p2, p3 está a la izquierda o a la derecha de la recta, o si la toca.

**Entrada:** 
- Un número `t`, el número de pruebas
- Después, `t` lineas con seis números enteros: x1, y1, x2, y2, x3 y y3.

**Salida:** Para cada prueba, imprime LEFT, RIGHT o TOUCH.

**Límites:**
- 1 ≤ t ≤ 10^5
- −10^9 ≤ x1, y1, x2, y2, x3, y3 ≤ 10^9
- x1 ≠ x2 or y1 ≠ y2
- De tiempo: 1 segundo
- De memoría: 512 MB

Traducida de: [CSES Problem Set – Point Location Test](https://cses.fi/problemset/task/2189)

## Concepto clave: producto cruz en 2D

Se usa el **producto cruz** para calcular de qué lado de una recta está otro punto.

```
  y
  ^                                     * p2 = (x2, y2)
  |   * p3: LEFT (resultado > 0)      /
  |                                 /
  |                               /
  |                             * p3: TOUCH (resultado = 0)
  |                           /
  |                         /             * p3: RIGHT (resultado < 0)
  |                       /
  |                     * p1 = (x1, y1)
  +-------------------------------------------------------------> x
```
Cada punto tiene dos coordenadas: p1 es (x1, y1), p2 es (x2, y2) y p3 es (x3, y3).

Construimos dos flechas que salen de p1: una que va a p2 y otra que va a p3. Luego calculamos:

(x2 - x1) * (y3 - y1) - (y2 - y1) * (x3 - x1)

Es decir: cuántos pasos hay de x1 a x2, por cuántos pasos hay de y1 a y3, menos cuántos pasos hay de y1 a y2, por cuántos pasos hay de x1 a x3.

El orden de la resta marca la dirección: restamos x1 y y1 porque miramos desde p1 hacia p2. Si miramos desde p2 hacia p1, el resultado cambia de signo y la izquierda y la derecha se invierten:

(x1 - x2) * (y3 - y2) - (y1 - y2) * (x3 - x2)

Cada flecha es un **vector**: un movimiento de cierta cantidad de pasos en x y en y.

- movimiento a p2: (x2 - x1, y2 - y1)
- movimiento a p3: (x3 - x1, y3 - y1)

Cada producto toma un número de cada movimiento:

- (x2 - x1) * (y3 - y1) = pasos en x del movimiento a p2 × pasos en y del movimiento a p3
- (y2 - y1) * (x3 - x1) = pasos en y del movimiento a p2 × pasos en x del movimiento a p3

Los números se cruzan: x por y, menos y por x. De ahí viene el nombre "producto cruz", y es lo que permite comparar las dos direcciones.

```
         w                      p1 *-----------------> v
        /                           \ )
       /                             \  θ
      /                               \
     /  θ                              \
    / )                                 \
p1 *-----------------> v                 w

w a la izquierda de v           w a la derecha de v
sin θ positivo → LEFT           sin θ negativo → RIGHT
```

En el dibujo, **v** es el movimiento de p1 a p2 y **w** es el movimiento de p1 a p3. Una flechita encima de la letra v (o w) se usa para indicar que es un vector.

**θ** (la letra griega *theta*) es cuánto giramos para pasar de mirar en la dirección de v a mirar en la dirección de w. **sin θ** (seno de theta) dice qué tan arriba o abajo queda la punta después de girar: positivo si giramos a la izquierda, negativo si giramos a la derecha, y cero si no giramos.

El signo del resultado nos da la respuesta:

- positivo → p3 está a la izquierda (LEFT)
- negativo → p3 está a la derecha (RIGHT)
- cero → p3 toca la recta (TOUCH)

## Panorama del código

Para la entrada, el programa lee `t` y guarda cada prueba como una lista de seis números enteros. Todas estas listas van dentro de una lista principal para facilitar el recorrido de las pruebas, una por una, a través de un ciclo `for`, así como la asignación de los seis números a las variables x1, y1, x2, y2, x3 y y3 en un solo paso, dentro de una función.

Luego, ese ciclo `for` recorre la lista de listas y, para cada prueba, llama a la función que calcula el producto cruz. Si el resultado es positivo, la función regresa "izquierda"; si es negativo, regresa "derecha"; y si es cero, regresa "tocando". Por último, el ciclo imprime lo que regresa la función.

## Análisis del código

- **Variables y tipos de datos:**
  - `int`: `num` (el número de pruebas), las seis coordenadas `x1`, `y1`, `x2`, `y2`, `x3`, `y3` y `product`. Como las coordenadas son enteras, el producto cruz es exacto: `product == 0` no tiene errores de redondeo.
  - `float`: los valores t, el punto P, `ab_length` y `best`. Salen de divisiones y raíces cuadradas, así que tienen decimales; por eso `on_wall` no pregunta si el resultado es exactamente 0, sino si es casi 0: menor que un margen muy pequeño, `1e-7` (0.0000001).
  - `bool`: `ok` (si AB está dentro) y `result` en `inside` (dentro o fuera; cambia en cada cruce).
  - `str`: solo al leer la entrada, antes de convertirla a `int`.

- **Estructuras de datos:**
  - Lista `coord`: guarda los seis números de una prueba, que se separan en un solo paso: `x1, y1, x2, y2, x3, y3 = coord`.
  - Lista de listas `coords`: guarda todas las pruebas para recorrerlas una por una con un ciclo `for`.

- **Paradigma algorítmico:** ninguno en particular; es un cálculo directo. No hay posibilidades que probar: una sola fórmula da la respuesta. En geometría computacional, esta prueba se llama primitiva geométrica: una pieza básica que se usa dentro de algoritmos más grandes.

- **Estilo de programación:** imperativo/procedural, con una función pequeña, `cross`, que responde una sola pregunta: de qué lado de la recta está p3.

- **Iterativo o recursivo:** iterativo. Un ciclo `for` lee la entrada y otro recorre las pruebas. No hay nada que dividir en problemas más pequeños, así que la recursión no ayuda

- **Complejidad:**
  - Temporal: O(1) por prueba, porque la fórmula siempre hace las mismas operaciones. En total, O(t).
  - Espacial: O(t), porque `coords` guarda todas las pruebas. Si cada prueba se resolviera al leerla, sería O(1).
